# 俱乐部标准基本面工作流

以下命令均在 `crawler-server` 目录执行。`CUP_ANALYZER_CUP` 决定从哪个赛事赛程中识别球队，但产物由球队 ID 决定写入哪个球队对象。

## FC 首尔验证流程

原始抓取与国内比赛分析仍复用现有爬虫。首次抓取前，在 `config/squadTarget.js` 中把球队、联赛和轮次改为 FC 首尔当前参数，然后运行：

```bash
npm run crawl:player-list:club
npm run analyze:club-domestic
```

从原始分析开始，后续命令不再依赖球队名称目录：

```bash
CUP_ANALYZER_CUP=koreanKLeague node processors/leagueSquadProcessor.js --team 741
CUP_ANALYZER_CUP=koreanKLeague node processors/squadFinalInitializer.js --team 741
```

第二条命令只创建待人工确认文件。核对：

`club-football/teams/fc-seoul/seasons/2026/fundamentals/squad-final/confirmed.md`

确认完成后，把文件首行：

```text
<!-- confirmation-status: pending -->
```

改为：

```text
<!-- confirmation-status: confirmed -->
```

然后才能运行：

```bash
CUP_ANALYZER_CUP=koreanKLeague node processors/teamProfileGenerator.js --team 741
CUP_ANALYZER_CUP=koreanKLeague node processors/historyMatchGenerator.js --team 741
```

## 比赛、盘口和热度

先创建中立比赛对象，四项参数都必须来自真实赛程：

```bash
npm run object:match:init -- --match <matchId> --competition <competition> --kickoff <ISO时间> --home <主队ID> --away <客队ID>
```

在不同时间点追加盘口快照：

```bash
npm run crawl:market-snapshot -- --match <matchId> --checkpoint opening
npm run crawl:market-snapshot -- --match <matchId> --checkpoint analysis
npm run crawl:market-snapshot -- --match <matchId> --checkpoint lineup
npm run crawl:market-snapshot -- --match <matchId> --checkpoint closing
npm run analyze:market -- --match <matchId>
```

热度分析读取比赛事实目录中的 `facts/heat-signals.json`。文件不存在时仍可执行分析，但结果会明确标记为 `blocked`，不会生成任何投注比例兜底值：

```bash
npm run analyze:heat -- --match <matchId>
```

## 世界杯兼容性

世界杯继续使用原有 `CUP_ANALYZER_CUP=theWorldCup` 命令、分组目录和人工确认流程。俱乐部球队对象初始化器会拒绝世界杯上下文，防止国家队状态进入 `club-football`。
