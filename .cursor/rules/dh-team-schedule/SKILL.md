# 球队赛程查询

根据用户指定的球队和日期范围，从仓库中的球队配置与赛程 JSON 输出赛程列表。曼城只是一个示例，球队和时间范围都必须以当前用户请求为准。

## 查询步骤

1. 从用户请求中识别球队、开始时间和结束时间。接受用户实际提供的时间范围，不要固定使用示例中的球队或日期。用户只给日期时，开始边界从当天 `00:00` 起，结束边界包含当天；用户给出具体时刻时，按其时刻筛选。
2. 在 `cup-analyzer/*/data/config.json` 中查找球队所属联赛配置。使用 `team` 对象内的 `dqdName`、`qiutanName` 匹配用户给出的球队名称，并记录该球队对象的配置键和 `qiutanSerial`。如果用户指定了联赛，优先使用该联赛目录；若名称对应多个配置且请求无法判定应使用哪个，询问用户，不要猜测。
3. 读取 `cup-analyzer/crawler-server/output/{qiutanSerial}-schedule.json`。根据配置键对应的球队 ID 以及配置中的球队名称，识别赛程记录中的目标球队；主客队方向均要处理。赛程 JSON 可能包含多个赛事，因此应包含所给时间范围内该队的所有比赛，而不是只列联赛比赛。
4. 按 `start_play` 排序并筛选起止日期内的比赛。使用记录的 `competition_name`、开球日期和时间。日期使用 `M月D日`，星期使用中文“周一”至“周日”，时间使用 24 小时制 `HH:mm`。如果范围跨越多个年份，在日期中保留年份以避免歧义。
5. 按目标球队在赛程中的主客队位置排列比分：目标队为 `team_A` 时使用 `fs_A-fs_B`，目标队为 `team_B` 时使用 `fs_B-fs_A`。比分字段为空时不编造比分，写成“目标队 vs 对手”。
6. 为每场比赛计算与上一场的间隔：在该球队赛程文件的所有比赛中（包括查询范围之外、其他赛事的比赛）按 `start_play` 排序，取当前比赛前一场目标队比赛，并用两场 `start_play` 相减得到小时数。沿用赛程文件的时间，不自行转换时区；若有分钟差，小时数保留一位小数，整数小时不显示小数。将间隔以 `N小时` 放在每行末尾，它表示距离上一场比赛的开球时间间隔。若文件中没有更早一场比赛，明确写“上一场间隔无法计算”，不要虚构数值。

## 输出格式

每场比赛一行，按时间升序：

`10月17日 周六 22:00 英超 曼城 3-2 伊普斯维奇 168小时`

未开赛且比分为空时，例如：

`10月20日 周二 19:00 欧冠 曼城 vs 雅典AEK 77小时`

如果时间范围内没有比赛，说明本地赛程文件中该时间段没有该队比赛。配置、序号或赛程文件缺失时，指出实际缺失的配置项或路径；不要推测联赛、序号、赛程、比分或间隔。
