# 足球新闻情绪系统学习路线

## 1. 学习目标

这条路线的最终目标是完成一套可验证、可训练、可部署、可持续改进的足球新闻情绪系统。

系统需要解决的核心问题是：

> 判断一条新闻对指定球队是正面、中性还是负面。

预期的完整流程：

```text
足球新闻
+ 目标球队
    ↓
足球专用 Transformer 分类模型
    ↓
positive / neutral / negative
    ↓
新闻去重、时间权重、来源权重
    ↓
球队新闻情绪指数
    ↓
人工复核、错误分析和持续训练
```

核心原则：先证明单条新闻的分类结果有效，再设计整体情绪指数。

---

## 2. 第一阶段：明确问题和标签规则

**建议时间：第 1 周**

### 2.1 明确分析目标

足球领域至少存在三种不同的情绪问题：

1. 新闻的措辞是否积极。
2. 新闻事件对目标球队是否有利。
3. 球迷当前是否兴奋、失望或愤怒。

第一版只解决第二个问题：新闻事件对指定球队的影响。

固定输入格式：

```text
目标球队：阿森纳
新闻：曼城击败阿森纳晋级决赛
```

期望输出：

```text
negative
```

同一条新闻在目标球队变化后，标签可能相反。

### 2.2 编写《标注规则》

标注规则至少需要覆盖：

- `positive`、`neutral`、`negative` 的明确定义；
- 胜负、晋级、淘汰和降级；
- 转会、续约、租借和解约；
- 伤病、停赛和复出；
- 教练下课和更衣室问题；
- 俱乐部财政、处罚和经营问题；
- 否定、转折、传闻和澄清；
- 一条新闻涉及多支球队时的处理方式；
- 无法确定时的处理规则。

### 2.3 本阶段产物

- 一份完整的足球新闻标注规则；
- 每个标签至少准备 20 个示例；
- 一组专门覆盖否定和转折的边界示例。

## 4. 第三阶段：学习机器学习基础

**建议时间：第 3 周**

### 4.1 必须理解的概念

- 监督学习；
- 文本分类；
- 特征和标签；
- 训练集、验证集和测试集；
- 过拟合和欠拟合；
- 数据泄漏；
- 类别不平衡；
- Precision、Recall 和 F1；
- Macro-F1；
- 混淆矩阵。

### 4.2 暂时不需要学习

### 4.3 评估原则

## 5. 第四阶段：建立传统模型基线

**建议时间：第 4 周**

在学习 Transformer 之前，先建立可对比的简单模型。

### 5.1 建议基线

1. 足球关键词规则。
2. SnowNLP 默认模型。
3. TF-IDF + Logistic Regression。

### 5.2 为什么要建立基线

基线模型用来回答：

> Transformer 是否真的比简单规则和传统模型更好？

所有模型必须使用同一份测试集：

| 模型 | Macro-F1 | positive Recall | neutral Recall | negative Recall |
|---|---:|---:|---:|---:|
| 关键词规则 | 待测试 | 待测试 | 待测试 | 待测试 |
| SnowNLP | 待测试 | 待测试 | 待测试 | 待测试 |
| TF-IDF | 待测试 | 待测试 | 待测试 | 待测试 |
| MacBERT | 待测试 | 待测试 | 待测试 | 待测试 |

## 6. 第五阶段：建设足球新闻数据集

**建议时间：第 4～6 周**

数据集是整个系统最重要的资产。

### 6.1 建议数据格式

```csv
id,event_id,target_team,title,content,label,source,publish_time
1,match_001,阿森纳,曼城击败阿森纳晋级决赛,...,negative,...,...
2,match_001,曼城,曼城击败阿森纳晋级决赛,...,positive,...,...
```

### 6.2 数据划分规则

- 同一事件的新闻必须放在同一个数据集中；
- 不能让同一场比赛的转载分别进入训练集和测试集；
- 重复新闻和转载新闻必须去重；
- 测试集应尽量保留较新的赛事和事件；
- 三个标签要保持合理数量；
- 数据集划分后，测试集不再参与日常调参。

### 6.3 数据规模路线

1. 标注 100～300 条，验证标签规则。
2. 扩充到 1000～3000 条，训练第一版专用模型。
3. 统计模型的主要错误类型。
4. 针对性增加伤病、转会、淘汰、否定和转折样本。
5. 持续积累高质量人工复核数据。

### 6.4 标注工具

可以用 Vue 实现一个简单标注页面：

```text
新闻标题和正文
目标球队
[正面] [中性] [负面]
[上一条] [下一条]
[标记争议样本]
```

## 9. 第八阶段：错误分析和数据迭代

**建议时间：第 9 周**

不能只看一个总分。需要人工检查错误样本并进行分类。

| 错误类型 | 示例 |
|---|---|
| 否定 | 俱乐部否认主帅即将下课 |
| 转折 | 虽然失利，但成功晋级 |
| 目标错位 | 曼城击败阿森纳 |
| 伤病程度 | 伤势并无大碍 |
| 转会传闻 | 双方尚未达成协议 |
| 时间变化 | 此前受伤，目前已经复出 |
| 标题党 | 标题负面，正文实际在澄清 |

每次迭代遵循：

```text
发现错误类型
→ 检查标注规则
→ 修正错误数据
→ 补充同类高质量样本
→ 重新训练
→ 使用同一测试集对比
```

## 10. 第九阶段：导出 ONNX 并使用 Transformers.js

**建议时间：第 10 周**

### 10.1 建议的第一版架构

```text
Vue / React
→ Node.js API
→ Transformers.js
→ q8 ONNX 足球情绪模型
```

第一版优先放在 Node.js 服务端推理，而不是让每个浏览器下载整个模型。

### 10.2 需要学习的内容

- ONNX 模型格式；
- q8 量化；
- Transformers.js `pipeline()`；
- Node.js 模型单例；
- 批量推理；
- 模型缓存；
- 文本长度限制；
- WASM 和 WebGPU 的区别。

### 10.3 目标代码形式

```ts
import { pipeline } from '@huggingface/transformers';

const classifier = await pipeline(
  'text-classification',
  'your-account/football-sentiment-onnx',
  {
    dtype: 'q8'
  }
);

const result = await classifier(
  '目标球队：阿森纳。新闻：阿森纳完成绝杀晋级决赛'
);
```

参考资料：

- [Transformers.js 文档](https://huggingface.co/docs/transformers.js/index)
- [Hugging Face Optimum ONNX 导出文档](https://huggingface.co/docs/optimum-onnx/onnx/usage_guides/export_a_model)

## 11. 第十阶段：设计球队情绪指数

**建议时间：第 11 周**

只有单条新闻分类通过验证后，才开始设计整体指标。

### 11.1 最小可用的情绪映射

```text
positive = 1
neutral = 0
negative = -1
```

### 11.2 新闻权重

```text
单条新闻权重
= 时间权重 × 来源权重 × 去重权重
```

### 11.3 球队情绪指数

```text
球队情绪指数
= Σ(情绪值 × 单条新闻权重)
  ÷ Σ单条新闻权重
```

然后再根据业务展示需要映射到 `0～100`。

### 11.4 第一版只保留的指标

- 总体情绪指数；
- 正面、中性和负面新闻占比；
- 最近 7 天的情绪趋势；
- 新闻分歧度；
- 有效新闻数量。

指标权重和阈值必须明确写成业务定义，不能将它们描述成模型准确率或胜率。

## 12. 第十一阶段：持续监控和维护

**建议时间：第 12 周以后**

上线后需要持续执行：

- 定期抽查模型结果；
- 保存用户和人工纠错；
- 记录新球员、新球队和新表达；
- 分别检查联赛、杯赛和转会窗新闻；
- 定期重新训练；
- 保留每个数据集和模型版本；
- 新模型必须使用固定测试集与旧模型对比；
- 只有新模型确实更好时才替换旧模型。

## 13. 阶段里程碑

### 里程碑 A：标注规则可用

- 完成标注规则；
- 完成 100～300 条人工标注；
- 能解释每条数据的标签理由；
- 能稳定处理同一新闻对不同球队的相反影响。

### 里程碑 B：建立可对比基线

- 完成关键词模型；
- 完成 SnowNLP 评估；
- 完成 TF-IDF 评估；
- 保存统一的测试报告。

### 里程碑 C：第一个足球 Transformer

- 积累 1000～3000 条较高质量标注数据；
- 完成 MacBERT 微调；
- 与所有基线模型对比；
- 完成混淆矩阵和错误分析。

### 里程碑 D：JavaScript 可部署

- 导出 ONNX；
- 完成 q8 量化；
- 通过 Transformers.js 运行；
- 通过 Node.js API 返回三分类结果；
- 保证前端输入格式与训练格式一致。

### 里程碑 E：情绪系统可验证

- 单条新闻分类通过独立测试；
- 完成新闻去重；
- 完成基础情绪指数；
- 指标定义、权重和阈值可追溯；
- 建立持续纠错和模型迭代机制。

---

## 14. 最终验收标准

一个可称为“真正有效”的足球新闻情绪系统，至少应该具备：

- 明确且一致的标签规则；
- 将目标球队作为模型输入；
- 独立且无事件重复的测试集；
- 与关键词、SnowNLP 和 TF-IDF 基线比较；
- Macro-F1、各类别指标和混淆矩阵；
- 人工错误分析；
- 可追溯的数据集和模型版本；
- 可通过 Transformers.js 部署的 ONNX 模型；
- 模型分类概率与业务情绪指数明确分离；
- 持续人工复核和重新训练机制。

---

## 15. 学习优先级

从现在开始，按以下顺序执行：

1. 编写《足球新闻标注规则》。
2. 人工标注第一批新闻。
3. 学习最少必要的 Python 和机器学习概念。
4. 建立关键词、SnowNLP 和 TF-IDF 基线。
5. 学习 Transformer 文本分类。
6. 微调 MacBERT。
7. 做错误分析和数据迭代。
8. 导出 ONNX 并接入 Transformers.js。
9. 在分类效果通过验证后设计情绪指数。
10. 建立持续监控、纠错和重新训练机制。
