# 第一阶段产物

第一阶段的产物不是模型，也不是训练代码，而是“判题标准 + 带标准答案的样本”。

可以具体输出成三个文件：

```text
football-sentiment/
├── 足球新闻标注规则.md
├── 足球新闻标注示例.csv
└── 足球新闻边界案例.csv
```

## 产物一：足球新闻标注规则.md

这是给标注人员看的说明书，也决定模型最终学习什么。

内容大致如下：

```md
# 足球新闻情绪标注规则

## 1. 标注目标

判断新闻事件对指定目标球队的影响。

不是判断文章语气是否激烈，也不是预测球队下一场是否获胜。

## 2. 标签定义

### positive

新闻中已经发生或明确确认的事件，对目标球队有直接正面影响。

例如：

- 获胜、晋级、夺冠；
- 主力球员伤愈复出；
- 成功续约核心球员；
- 引进重要球员；
- 竞争对手失分，使目标球队排名获益。

### negative

新闻中已经发生或明确确认的事件，对目标球队有直接负面影响。

例如：

- 失利、淘汰、降级；
- 主力球员受伤或停赛；
- 核心球员离队；
- 俱乐部受到处罚；
- 教练与球员发生公开冲突。

### neutral

新闻只是客观陈述，或者没有明确说明对目标球队产生正面或负面影响。

例如：

- 公布比赛时间；
- 发布训练照片；
- 介绍球队历史；
- 尚未得到确认的普通传闻；
- 新闻只提到球队，但没有发生具体影响。

## 3. 无法确定的处理方式

无法判断时，不要强行标记为 neutral。

将记录标记为“需要复核”，由人工再次判断。
```

这里要特别注意：

> `neutral` 表示新闻影响确实中性；“我不知道怎么判断”不等于中性。

## 产物二：足球新闻标注示例.csv

这是第一批“带标准答案”的数据，模型以后会学习这些内容。

推荐字段：

```csv
id,event_id,target_team,title,content,label,reason
```

实际内容类似：

```csv
id,event_id,target_team,title,content,label,reason
1,match_001,阿森纳,阿森纳击败切尔西,阿森纳主场2比0击败切尔西,positive,目标球队赢得比赛
2,match_002,阿森纳,曼城击败阿森纳,阿森纳客场0比2不敌曼城,negative,目标球队输掉比赛
3,match_003,阿森纳,比赛时间确定,阿森纳将在周六晚上迎战热刺,neutral,只公布比赛安排
4,injury_001,阿森纳,萨卡伤愈复出,萨卡已经恢复合练并可以参加下一场比赛,positive,核心球员恢复比赛资格
5,injury_002,阿森纳,萨卡将伤缺六周,萨卡因腿部受伤预计缺席六周,negative,核心球员无法参加比赛
6,transfer_001,阿森纳,阿森纳与核心球员完成续约,双方签署了一份新的长期合同,positive,核心球员确定留队
```

`reason` 非常重要，因为在刚接触这个领域时，它可以帮助发现标注规则是否一致。

第一周不用标注几千条，先准备：

```text
positive：20条
neutral：20条
negative：20条
合计：至少60条
```

## 产物三：足球新闻边界案例.csv

这个文件专门收集容易判断错误的新闻。

推荐字段：

```csv
id,case_type,target_team,text,label,reason,review_status
```

例如：

```csv
id,case_type,target_team,text,label,reason,review_status
1,转折,阿森纳,阿森纳虽然输掉次回合但凭借总比分成功晋级,positive,主要比赛结果是成功晋级,confirmed
2,否定,阿森纳,阿森纳否认主教练即将下课,neutral,下课事件没有得到确认,confirmed
3,否定,阿森纳,萨卡的伤势并无大碍并可以参加下一场比赛,positive,明确确认球员可以出场,confirmed
4,传闻,阿森纳,消息称阿森纳可能签下一名前锋,neutral,转会尚未确认,confirmed
5,多球队,阿森纳,曼城击败阿森纳晋级决赛,negative,目标球队阿森纳被淘汰,confirmed
6,多球队,曼城,曼城击败阿森纳晋级决赛,positive,目标球队曼城获胜并晋级,confirmed
7,混合事件,阿森纳,阿森纳赢得比赛但主力前锋严重受伤,,同时存在明显利好和利空,needs_review
```

最后一条先不填写 `label`，因为它需要明确规则：

- 按比赛结果判断；
- 按最严重事件判断；
- 拆成两个事件分别判断；
- 或者增加 `mixed` 标签。

第一版建议拆成两个事件，不要强行用一个标签概括：

```text
事件一：阿森纳赢得比赛 → positive
事件二：主力前锋严重受伤 → negative
```

## 第一阶段结束时应该看到什么

最终应该有：

```text
1份标注规则
+ 至少60条普通示例
+ 20～30条边界案例
```

大约是下面这种规模：

| 产物 | 内容 |
|---|---|
| 标注规则 | 正面、中性、负面的统一定义 |
| 普通示例 | 胜负、转会、伤病、处罚等标准样本 |
| 边界案例 | 否定、转折、传闻、多球队、混合事件 |
| 判断理由 | 每条样本为什么属于这个标签 |
| 复核状态 | 是否已经确认，还是存在争议 |

## 第一阶段的验收方式

> 过几天后重新看同一批新闻，仍然能够按照规则给出相同标签；另一个人阅读规则后，也能得到基本一致的判断。

如果同一条新闻今天标成正面、明天又标成中性，说明标注规则还不够明确，暂时不应该开始训练模型。
